# GoChiroMobile Platform

The public GoChiroMobile website and online appointment scheduler. The application combines a content-led marketing site with a mobile-first booking funnel backed by Google Calendar and Gmail.

## What is in this repository

### Website

The App Router marketing site lives in `app/(marketing)` and includes:

- `/` — homepage and booking entry points
- `/about`, `/philosophy`, and `/what-to-expect` — practice and care information
- `/pricing` — prices sourced from the scheduler's live visit configuration
- `/service-areas` and `/service-areas/[slug]` — ZIP coverage and local-area landing pages
- `/contact` — public contact details
- `/book-online` — entry page for new-patient, returning-patient, and group bookings

Shared navigation, footer, local-area content, ZIP checking, and design primitives are in `components/` and `lib/localAreas/`. Global styling is in `app/globals.css`. Remote marketing images are served from the Cloudinary path allowed by `next.config.ts`.

### Scheduler

The scheduler UI is at `/book`; marketing links can deep-link to a flow with `?start=new`, `?start=returning`, or `?start=group`.

- `app/book/page.tsx` owns the multi-step client flow, validation, slot funnel, review, and confirmation states.
- `lib/gochiro.ts` is the canonical configuration for service ZIPs, tiers, visit prices and durations, lead times, payment links, and group calculations.
- `GET /api/slots` validates a date and visit, reads Google Calendar, applies business hours, travel buffers, conflicts, and per-visit lead time, and returns ISO timestamps.
- `POST /api/book` validates the request again, rechecks that the chosen time is free, creates the calendar event, and then makes a best-effort attempt to send patient and practice emails.
- `lib/scheduling.ts` computes 30-minute candidate starts and applies same-region or cross-region travel buffers.
- `lib/timezone.ts` keeps business-day calculations in `America/New_York`, independent of the deployment server's timezone.

Maintenance / Wellness Visits require **48 hours of advance notice**. This is enforced by both the displayed booking flow and the server-side slot/booking checks. See [`BOOKING_FLOW_SPEC.md`](./BOOKING_FLOW_SPEC.md) for the complete implemented behavior.

## Local development

### Prerequisites

- Node.js compatible with Next.js 16
- npm
- A Google Workspace service-account key with domain-wide delegation when exercising live scheduler APIs

Install dependencies and start the development server:

```bash
npm ci
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Marketing pages do not need Google credentials, but availability and booking requests do.

### Environment variables

Create an untracked `.env.local` and configure one credential source:

```dotenv
# Recommended for Vercel/production: the complete service-account JSON object.
GOOGLE_SERVICE_ACCOUNT_KEY_JSON='{"client_email":"...","private_key":"..."}'

# Local alternative: absolute path to the downloaded JSON key.
# GOOGLE_SERVICE_ACCOUNT_KEY_PATH=/absolute/path/service-account.json

# Optional overrides; defaults are defined in the integration modules.
GOCHIRO_CALENDAR_OWNER=contact@mybackcracker.com
GOCHIRO_CALENDAR_ID=contact@mybackcracker.com
GOCHIRO_EMAIL_SENDER=contact@mybackcracker.com

# Secure intake issuance (keep disabled until the intake app validates and consumes tokens)
GOCHIRO_INTAKE_LINKS_ENABLED=false
GOCHIRO_INTAKE_AUTH_SPREADSHEET_ID=synthetic-staging-sheet-id
GOCHIRO_INTAKE_BASE_URL=https://staging-intake.example.invalid/
```

Do not commit credentials. The delegated account requires these scopes:

- `https://www.googleapis.com/auth/calendar`
- `https://www.googleapis.com/auth/gmail.send`
- `https://www.googleapis.com/auth/spreadsheets` (only for the dedicated intake ledger)

Patient mail is sent with the public GoChiroMobile address as a verified Gmail “Send mail as” alias. The authenticated mailbox, configured by `GOCHIRO_EMAIL_SENDER`, remains the delegated Workspace identity.

### Protected intake-authorization ledger

Create a **dedicated**, access-restricted Google Sheet manually; the application never creates or repairs it. Name its tab `Intake Authorizations` and place this exact header row in columns A–G:

```text
Token Hash | Appointment Reference | Expires At UTC | Status | Created At UTC | Consumed At UTC | Revoked At UTC
```

Share only that Sheet with the existing service account's `client_email` as an editor. Grant the delegated credential the least-privilege Sheets scope `https://www.googleapis.com/auth/spreadsheets`; do not grant Drive scope. The ledger contains only a SHA-256 token hash, opaque Calendar event ID, UTC expiration, status, UTC creation time, and initially blank consumption/revocation times—never raw tokens or PHI.

For synthetic staging, create a separate non-production Sheet, use the exact tab/header schema above, share it with a staging service account, point the three intake environment variables at synthetic endpoints/IDs, and book only invented patients against a non-production calendar. Verify with the flag `false` first, then set it to exactly `true`. Never commit spreadsheet IDs, deployment URLs, credentials, secrets, tokens, or patient information.

Tokens are generated from 256 random bits, base64url encoded without padding, domain-separated and SHA-256 hashed before storage. New-patient links expire at the earlier of three hours after server-side booking time or appointment start and are designed for one use. Maintenance, priority, care-plan, and group visits do not receive links; group intake remains unsupported pending a multi-patient design.

**Production blocker:** the separate intake application must implement server-side token validation and atomic single-use consumption before `GOCHIRO_INTAKE_LINKS_ENABLED=true` is used in production. This repository issues authorizations only.

Rollback requires no code or Sheet changes: set `GOCHIRO_INTAKE_LINKS_ENABLED=false` exactly and redeploy the scheduler configuration. Existing appointments remain booked; separately revoke outstanding rows according to practice procedure if required.

## Operational behavior

- Business hours are Monday–Thursday, 9:00 AM–6:00 PM Eastern. Friday closes at 4:00 PM, except Main Line and West Chester, which close at 2:00 PM. The close is an allowed slot start.
- Saturdays and Sundays are unavailable.
- Existing calendar events block overlaps. Recognized region labels also add configured travel time before and after an event.
- Booking creation rechecks the selected slot to reduce double-booking races.
- Calendar creation is the booking success boundary. Email failures are logged but do not undo a successful appointment.
- Prices, covered ZIP codes, Square links, public contact details, and booking notification addresses are configuration in `lib/gochiro.ts`; review changes there carefully.
